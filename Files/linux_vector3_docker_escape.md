# Analyst Guide: Linux Vector 3 - Docker Escape & Ransomware

## 1. Overview
Угрозы контейнерной инфраструктуры (Docker/K8s) — это ключевой тренд последних лет. В данном векторе злоумышленник (или вредоносный образ контейнера) получает возможность выполнить команду с флагом `--privileged` и примонтировать файловую систему сервера-хоста (`SERVER-1C`) внутрь контейнера. Используя этот доступ, хакер осуществляет побег (Escape to Host) путем записи в планировщик задач хоста (`/etc/cron.d/`). Наконец, он запускает программу-вымогатель (Linux Ransomware), которая шифрует тома Docker.

## 2. Detection & Triage

### KQL: Подозрительный запуск контейнера (Privileged + Volume Mount)
Ищем запуски Docker с опасными ключами, которые позволяют контейнеру взаимодействовать с ядром хоста.
```kql
event.dataset: "auditd.log"
  AND process.name: "docker"
  AND process.args: "--privileged"
  AND process.args: "-v"
```

### KQL: Создание файлов в директориях конфигурации системы
Отслеживание записи в системные директории `/etc/` или `/usr/bin` из подозрительных процессов (таких как процессы внутри контейнеров, например `sh` от пользователя root).
```kql
winlog.channel: "Linux-Sysmon/Operational"
  AND winlog.event_id: "11"
  AND file.path: /etc/cron.*/.*
```

### KQL: Запуск Ransomware из временных папок
Ищем процессы, порожденные демоном `cron`, которые запускают бинарники из `/tmp` или `/dev/shm`.
```kql
event.dataset: "auditd.log"
  AND process.parent.name: "cron"
  AND process.executable: (/tmp/* OR /dev/shm/*)
```

## 3. Investigation Steps

1. **Анализ SERVER-1C (192.168.100.7):**
   - Убедитесь, не был ли API Docker (`2375/tcp`) открыт наружу без аутентификации.
   - Изучите логи Docker-демона (`journalctl -u docker`), чтобы понять, кто и с какого IP-адреса инициировал создание привилегированного контейнера.
2. **Анализ ущерба (Ransomware):**
   - Проверьте, какие файлы и директории (например, `/var/lib/docker/volumes`) были зашифрованы процессом `/tmp/encryptor.elf`.

## 4. Containment & Remediation
- Немедленно остановите и удалите вредоносный контейнер.
- Удалите файл `/etc/cron.d/reverse_shell` и завершите процесс `encryptor.elf`.
- Настройте Docker Daemon для работы с TLS или запретите удаленный доступ к API (используйте только сокет).
- Избегайте запуска контейнеров от имени пользователя `root` и без `seccomp/apparmor` профилей.

# Investigation Checklist

- [ ] Вредоносный контейнер остановлен.
- [ ] Крон-задача и файл шифровальщика удалены с хостовой машины.
- [ ] Конфигурация Docker Daemon проверена на предмет открытого порта 2375/tcp.
- [ ] Оценка зашифрованных данных завершена, начат процесс восстановления из резервных копий.
