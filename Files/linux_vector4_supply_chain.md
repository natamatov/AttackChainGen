# Analyst Guide: Linux Vector 4 - Supply Chain Backdoor

## 1. Overview
В данном сценарии имитируется атака на цепочку поставок (по типу инцидента с библиотекой `xz`/`liblzma`). Легитимный администратор сервера `mil02` обновляет систему через `apt-get upgrade`. Один из обновленных пакетов содержит вредоносный код, который на уровне динамических библиотек встраивается в службу `sshd`. Это позволяет злоумышленнику использовать специальный (захардкоженный) ключ, чтобы войти в систему по SSH под видом легитимного входа и выгрузить конфиденциальные данные (файл `shadow`).

## 2. Detection & Triage

### KQL: Обновление системы перед инцидентом
Отслеживаем использование пакетных менеджеров (`apt`, `yum`, `dpkg`) в моменты, предшествующие аномальному поведению SSH.
```kql
event.dataset: "auditd.log"
  AND process.name: ("apt-get" OR "yum" OR "dpkg")
  AND process.args: ("upgrade" OR "install")
```

### KQL: Аномальный вход по публичному ключу
Поиск успешных входов по ключу (Accepted publickey) от IP-адресов, с которых ранее никогда не осуществлялся доступ.
```kql
event.module: "system" AND event.dataset: "system.auth"
  AND event.action: "ssh_login"
  AND auth_method: "publickey"
```

### KQL: Эксфильтрация системных файлов (shadow)
Мониторинг утилит `curl`/`wget`, запущенных процессом `sshd` и обращающихся к чувствительным системным файлам.
```kql
event.dataset: "auditd.log"
  AND process.name: "curl"
  AND process.command_line: */etc/shadow*
```

## 3. Investigation Steps

1. **Анализ сервера mil02 (192.168.100.6):**
   - Просмотрите логи `/var/log/apt/history.log` или `/var/log/dpkg.log`, чтобы определить, какие именно пакеты были установлены или обновлены в день инцидента.
   - Сравните контрольные суммы бинарников (особенно `/usr/sbin/sshd` и связанных с ним `.so` библиотек через `ldd /usr/sbin/sshd`) с официальными репозиториями (например, с помощью утилиты `debsums`).
2. **Анализ ущерба (Exfiltration):**
   - Был скопирован файл `/etc/shadow`. Это означает, что злоумышленник может начать оффлайн-перебор паролей локальных учетных записей сервера.

## 4. Containment & Remediation
- Заблокируйте IP-адрес 198.51.100.42.
- Откатите обновленные пакеты до предыдущих, заведомо безопасных версий.
- Инициируйте процедуру массового сброса паролей на `mil02`, так как хэши паролей утекли.
- Перезапустите службу SSH и обновите хостовые SSH-ключи.

# Investigation Checklist

- [ ] IP-адрес злоумышленника заблокирован.
- [ ] Источник компрометации (конкретный вредоносный `deb`/`rpm` пакет) идентифицирован.
- [ ] Произведен откат пакета на чистую версию.
- [ ] Пароли локальных пользователей на сервере сброшены.
- [ ] Опубликован внутренний Security Bulletin для запрета установки данного обновления на другие серверы инфраструктуры.
