# Analyst Guide: Linux Vector 1 - SSH Brute-Force & Key Theft

## 1. Overview
В данном сценарии злоумышленники проводят брутфорс-атаку (перебор паролей) на публично доступный почтовый сервер Linux (`mail01`). После множественных неудачных попыток им удается подобрать пароль пользователя `admin`. Получив доступ к серверу (Initial Access), они используют легитимную утилиту `nmap` для сканирования внутренней серверной подсети (Reconnaissance), подготавливая плацдарм для бокового перемещения.

## 2. Detection & Triage

### KQL: Множественные неудачные входы по SSH
Ищем всплески неудачных попыток входа с одного внешнего IP-адреса.
```kql
event.module: "system" AND event.dataset: "system.auth"
  AND event.action: "ssh_login"
  AND event.outcome: "failure"
```

### KQL: Успешный вход по SSH с подозрительного IP
Отслеживаем успешный вход (Accepted password/publickey) от IP-адреса, который ранее был замечен в брутфорсе.
```kql
event.module: "system" AND event.dataset: "system.auth"
  AND event.action: "ssh_login"
  AND event.outcome: "success"
  AND source.ip: "203.0.113.15"
```

### KQL: Использование инструментов сканирования (nmap)
Ищем запуски сетевых сканеров на серверах, где это не является нормой.
```kql
event.dataset: "auditd.log"
  AND process.name: "nmap"
  AND process.args: ("-sS" OR "-p")
```

## 3. Investigation Steps

1. **Анализ почтового сервера (192.168.100.5):**
   - Проверьте файл `/var/log/auth.log` или `/var/log/secure` на предмет точного времени брутфорса и используемых списков имен (usernames).
   - Изучите `.bash_history` пользователя `admin` (или логи auditd), чтобы узнать, какие команды вводил злоумышленник после входа.
   - Проверьте файл `~/.ssh/authorized_keys`, чтобы убедиться, что хакер не добавил свой ключ для закрепления в системе.
2. **Анализ сетевой активности:**
   - По логам NGFW проверьте, к каким еще серверам в подсети 192.168.100.0/24 обращался взломанный сервер `mail01`.

## 4. Containment & Remediation
- Немедленно заблокируйте IP-адрес атакующего на межсетевом экране.
- Сбросьте пароль пользователя `admin`.
- Отключите аутентификацию по паролю в `/etc/ssh/sshd_config` (установите `PasswordAuthentication no`) и переведите доступ только на ключи.
- Установите Fail2Ban для автоматической блокировки IP при брутфорсе.

# Investigation Checklist

- [ ] Вредоносный IP-адрес заблокирован (Blacklist).
- [ ] Пароль скомпрометированной УЗ изменен.
- [ ] Публичные ключи в `authorized_keys` пользователя `admin` проверены.
- [ ] Проверены другие серверы на предмет успешных SSH-сессий от скомпрометированного `mail01`.
