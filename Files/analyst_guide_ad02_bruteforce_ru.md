# Руководство аналитика: Brute Force атака на AD02

## 1. Обзор
Данное руководство содержит инструкции по расследованию инцидента типа **Brute Force** (полный перебор пароля), направленного на контроллер домена **AD02** (`192.168.100.2`) в домене `corp.local.uz`. 
В данном сценарии злоумышленник, действуя с захваченной рабочей станции **PC1** (`192.168.100.20`), осуществляет перебор пароля для встроенной учетной записи **administrator**. Атака характеризуется серией неудачных попыток входа по сети (Logon Type 3), завершающихся успешной аутентификацией.

## 2. Обнаружение и первичный анализ (Triage)

### Поиск аномальных всплесков авторизации
Атака проявляется как цепочка событий `Event ID 4625` (ошибка входа), за которыми следует событие `Event ID 4624` (успешный вход) с одного и того же IP-адреса для одной и той же учетной записи.

**KQL-запрос для поиска активности в Kibana / Elastic:**
```kql
winlog.event_id: ("4625" OR "4624") 
  AND host.name: "AD02" 
  AND winlog.event_data.TargetUserName: "administrator"
  AND winlog.event_data.IpAddress: "192.168.100.20"
  AND winlog.event_data.LogonType: "3"
```

**Ключевые индикаторы компрометации (IoC):**
*   **Target:** Контроллер домена `AD02` (192.168.100.2)
*   **Source IP (Attacker):** `192.168.100.20` (предположительно PC1)
*   **Target Account:** `administrator@corp.local.uz`
*   **Logon Type:** `3` (Network Logon — доступ по сети, например, через SMB/RPC)

## 3. Шаги расследования

### Шаг 1: Анализ источника (Source PC1)
*   Определено, что атака исходит с внутреннего IP-адреса `192.168.100.20` (PC1).
*   Поскольку IP является внутренним, необходимо срочно изолировать хост PC1 от сети.
*   Инициируйте расследование на рабочей станции PC1: проверьте запущенные процессы, недавние загрузки файлов и сетевые подключения, чтобы понять, как злоумышленник получил доступ к этой машине.

### Шаг 2: Анализ целевого аккаунта
*   Целью атаки является учетная запись `administrator` домена `corp.local.uz`. Это аккаунт с максимальными привилегиями (Domain Admin).
*   В логах будет видно 5 неудачных попыток входа (`4625`) с интервалом в 2 секунды.
*   Спустя 5 секунд после последней ошибки зафиксирован **успешный вход** (`4624`). Это означает, что пароль администратора домена был скомпрометирован.

### Шаг 3: Расследование последствий успешного входа
Поскольку атакующий получил доступ с правами Domain Admin через Network Logon (Type 3):
*   Проверьте создание новых подозрительных служб на AD02 (Event ID `4697` или `7045`).
*   Проверьте попытки доступа к административным шарам, таким как `C$` или `ADMIN$`.
*   Отследите создание новых процессов на AD02 (`Event ID 4688`), запущенных от имени `administrator` во временное окно после успешного входа.

## 4. Сдерживание и устранение последствий

*   **Изоляция источника:** Немедленно отключите рабочую станцию PC1 (`192.168.100.20`) от корпоративной сети для предотвращения дальнейшего распространения атаки.
*   **Сброс пароля:** Срочно сбросьте пароль учетной записи `administrator@corp.local.uz`, так как он был скомпрометирован.
*   **Отзыв активных сессий:** Принудительно завершите все активные сессии администратора на всех контроллерах домена и серверах.
*   **Аудит изменений:** Проверьте Active Directory на предмет создания новых учетных записей администраторов или изменения прав доступа за последние часы.
*   **Внедрение ограничений:** Рассмотрите возможность переименования встроенной учетной записи администратора и ограничения доступа к ней только с выделенных jump-хостов.

# Чек-лист расследования (Investigation Checklist)

## Первичный анализ (Triage)
- [ ] Подтвердить алерт: зафиксировано минимум 5 событий Event ID 4625 подряд для аккаунта `administrator` на `AD02`.
- [ ] Подтвердить успешный вход: зафиксировано событие Event ID 4624 для `administrator` с IP `192.168.100.20` с Logon Type 3.

## Анализ (Analysis)
- [ ] Идентифицировать исходный хост атаки: `192.168.100.20` (PC1).
- [ ] Убедиться, что это Network Logon (Type 3), что указывает на удаленную сетевую авторизацию.
- [ ] Проверить логи на `AD02` на наличие действий, выполненных от имени `administrator` после успешного входа.
- [ ] Начать параллельное расследование компрометации рабочей станции PC1 (`192.168.100.20`).

## Сдерживание и устранение (Containment & Remediation)
- [ ] Изолировать PC1 (`192.168.100.20`) от сети.
- [ ] Выполнить экстренный сброс пароля для `administrator@corp.local.uz`.
- [ ] Завершить все текущие сессии `administrator`.
- [ ] Проверить целостность группы Domain Admins.
- [ ] Задокументировать инцидент компрометации администратора домена.
